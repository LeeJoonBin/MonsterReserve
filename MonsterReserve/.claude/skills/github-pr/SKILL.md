# github-pr

사용자가 Push를 마친 작업을 PR로 작성해 등록하는 절차다.
이 스킬은 PR의 작성과 등록만 다룬다. 그 밖의 저장소 작업은 사용자가 직접 한다.

## 읽을 문서

- 작성 양식 : `Docs/Template/Pull Request Template.md`

## 절차

1. **정보 수집**
    - 관련 이슈 번호 (없으면 "없음")
    - 이번 업무의 검수 요청 내용 (변경 내용, 확인 결과, 사용자 확인 항목)
    - 작업 브랜치 이름과 기준 브랜치 이름은 사용자에게 묻는다.
2. **초안 작성** : 양식에 따라 제목과 본문을 쓴다. 본문은 임시 파일로 저장해 둔다.
    - 이슈 기반 업무면 본문에 `Closes #[이슈 번호]`를 넣어, 병합될 때 이슈가 닫히게 한다.
3. **승인** : 제목, 본문, 작업 브랜치, 기준 브랜치를 함께 보여 주고 승인을 받는다. 특히 기준 브랜치가 맞는지 다시 확인한다.
4. **등록** : 승인되면 GitHub CLI로 등록한다.

    ```bash
    gh pr create --base [기준 브랜치] --head [작업 브랜치] --title "[제목]" --body-file [본문 파일 경로]
    ```

    - `gh`가 설치되어 있지 않거나 로그인이 안 되어 있으면 등록하지 말고, 사용자가 직접 등록할 수 있도록 제목과 본문을 전달한다.
5. **보고** : 등록된 PR 번호와 주소를 알린다.

## 하지 않는 일

- 사용자 승인 없이 PR을 등록하거나 수정하지 않는다.
- PR을 병합하지 않는다. 병합은 사용자가 직접 한다.
