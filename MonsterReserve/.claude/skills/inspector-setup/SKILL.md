# inspector-setup

인스펙터 설정을 안전하고 확인 가능한 방식으로 하기 위한 절차다.
설정 하나를 잘못 연결하면 에디터에서는 조용히 넘어가고 실행 중에야 오류가 나기 쉬우므로, 무엇을 어디에 왜 넣었는지 모두 보고에 남긴다.

## 1. 대상 확인

- 어떤 씬 또는 프리팹의, 어떤 오브젝트의, 어떤 컴포넌트를 설정하는지 정한다.
- 사용자가 작성한 스크립트의 필드에 값을 넣거나 연결해야 하면, 스크립트를 읽어 `public` 또는 `[SerializeField]` 필드의 이름과 타입을 확인한다.
    - 필드의 의미가 이름만으로 분명하지 않으면 추측하지 말고 호출자에게 보고해 사용자 확인을 받는다.
    - 필요한 필드가 스크립트에 없으면 필드를 추가하지 않는다. 사용자 스크립트를 고치는 일이므로 보고만 한다.

## 2. 값의 출처 확인

- 넣을 값은 반드시 문서에 근거가 있어야 한다.
    - 조정 값 (탄속, 감지 거리, 무기 가격 등) : `Docs/Design/GameDesign.md`
    - 기술 규칙 (입력, 폴더 등) : `Docs/TechSpec.md`
    - 담당 영역의 값 : `Docs/UI/UI.md`, `Docs/World/MapLayout.md`, `Docs/Sound/Sound.md`
- 문서에 값이 없거나 "미정"이면 임의로 정하지 않고 보고한다.
- 문서에 "임시값"으로 적힌 값은 넣되, 보고에 임시값임을 표시한다.

## 3. 적용 방법 선택

아래 순서로 판단한다.

1. **프리팹, 씬 파일 직접 수정** : 숫자, 글자, 체크박스처럼 단순한 값은 `.prefab`, `.unity` 파일에서 해당 필드 값을 고친다.
2. **참조 연결** : 다른 오브젝트나 에셋을 연결하는 값은 파일 안에서 `{fileID, guid, type}` 형태로 저장된다. 에셋의 guid는 같은 이름의 `.meta` 파일에서 확인한다. 연결 대상을 정확히 찾지 못하면 직접 수정하지 말고 4번의 "안내"로 넘긴다.
3. **에디터 스크립트** : 많은 오브젝트에 같은 설정을 반복해야 할 때만 쓴다. 에디터 스크립트 작성은 `map-builder`에게만 허용된다. 다른 에이전트는 안내로 넘긴다.
4. **사용자 안내** : 위 방법으로 확실하게 적용할 수 없으면 파일을 고치지 않고, 사용자가 에디터에서 직접 넣을 수 있도록 설정표로 안내한다.

## 4. 하지 않는 일

- 사용자가 작성한 스크립트의 코드를 고치지 않는다.
- 에셋 스토어에서 가져온 폴더의 원본 프리팹과 파일을 고치지 않는다. 원본을 바꿔야 할 것 같으면 보고한다.
- 브리핑에서 승인받지 않은 오브젝트의 값을 바꾸지 않는다.

## 5. 보고

| --- | --- | --- | --- | --- | --- | --- | --- |
