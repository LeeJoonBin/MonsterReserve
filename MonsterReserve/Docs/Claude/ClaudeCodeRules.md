# Claude Code 행동 규칙

> 상시 로드 문서. Claude Code가 이 프로젝트에서 반드시 따라야 하는 행동 규칙.
> 절대 원칙은 `CLAUDE.md`에, 작업 분담과 서브에이전트 운용은 `WorkflowRules.md`에 있다.

---

## 행동 원칙

### 1. 사고 우선 (Think Before Coding)

> 가정을 숨기지 말고, 모호하면 멈춘다.

- 가정을 명시적으로 말한다. 불확실하면 질문한다.
- 해석이 여러 갈래라면, 모두 제시하고 임의로 고르지 않는다.
- 더 단순한 방법이 보이면 사용자에게 알린다.
- 코드를 읽기만 하고 세운 결론은 "미검증"인 상태로 표기한다.

### 2. 단순함 우선 (Simplicity First)

> 문제를 푸는 최소한의 코드만 작성하라.

- 요청 범위 밖의 기능을 추가하지 않는다.
- 한 번만 쓰는 코드에 추상화를 도입하지 않는다.
- 요청하지 않은 "확장성"이나, "가능성"을 미리 만들지 않는다.
- 일어날 수 없는 상황을 위한 예외처리를 작성하지 않는다.

### 3. 외과적 변경 (Surgical Changes)

> 필요한 곳만 건드려라.

- 인접 코드, 주석, 포멧팅을 임의로 "개선" 하지 않는다.
- 구동에 문제가 없는 코드를 리팩토링 하지 않는다.
- 본인 변경 때문에 쓰이지 않게 된 변수, 함수는 정리한다. 원래 있던 죽은 코드는 보고만 한다.

**판단 기준** : 변경을 가하는 모든 행위는 사용자의 결정에서 직접 나와야 한다.

### 4. 검증 가능한 목표 (Goal-Driven Execution)

> 성공 기준을 먼저 정하고, 확인될 때까지 진행한다.

- 여러 단계로 작업을 나눠야 할 경우를 포함한 모든 상황에서 작업 계획을 브리핑한다.

```
1. [단계 명] -> 확인 : [확인 항목], [확인 항목]
2. [단계 명] -> 확인 : [확인 항목], [확인 항목]
```

---

## 작업 범위 규칙

- 요청(승인)받은 파일과 기능 외의 코드는 수정하지 않는다.
- 다른 파일에서 문제를 발견하면 보고만 하고 수정하지 않는다.
- 한 번에 구현 단계 하나만 작업한다.

---

## 기능 구현 착수 규칙

> 기능 구현을 요청받으면 바로 작업하지 않고, 아래 형식으로 먼저 **브리핑**한 뒤 **승인**을 받고 착수한다.
> UI, 인스펙터 설정, 맵 배치처럼 씬, 프리팹, 컴포넌트를 다루는 작업도 같은 형식으로 브리핑한다.

```
## 구현 브리핑 : [기능명]

**작업 범위**
(구현 내용 요약)

**생성/수정 파일**
- 생성 : 파일경로(역할)
- 수정 : 파일경로(변경 내용)

**작업 순서** (`4. 검증 가능한 목표 (Goal-Driven Execution)`의 포멧)
1. 단계 1
2. 단계 2

진행할까요?
```

문서와 오타 등 코드가 아닌 단순 수정은 브리핑하지 않는다.

---

## 범위 관리

- 이 프로젝트는 1인 개발 포트폴리오다. 볼륨보다 핵심 시스템 완성을 우선한다.
- 범위를 넓히는 기능은 제안만 하고, `Docs/Design/GameDesign.md`의 "추후 추가"에 기록하도록 사용자에게 알린다.

---

## 의도된 동작

- 결정 기록에 "의도적으로 남겨 둠"으로 적힌 동작은 버그로 보고 고치지 않는다.
- 예: 사망 화면에서 강제 종료하면 저장 데이터가 지워지지 않아 마지막 저장 시점으로 돌아간다 (재도전으로 허용).

---

## 응답 규칙

- 소스코드의 주석은 한국어로 작성한다.
- 변수, 함수, 클래스 이름은 네이밍 컨벤션(`Docs/Code/code-convention.md`, 작성 예정)을 따른다.
- 불필요한 코드, 쓰지 않는 변수, 빈 메서드는 만들지 않는다.
- 핵심 부분에 짧은 설명을 붙인다.
