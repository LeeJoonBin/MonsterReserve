## 작업 방식

> 결정 : 2026-11-09. 넓은 면적은 규칙 기반으로 채워 토큰과 성능을 아끼고, 눈에 띄는 좁은 곳만 직접 다듬는다.

| 방식 | 쓰는 곳 |
| --- | --- |
| Unity Terrain | 바탕 지면, 높은 지형, 바닥 식생 (Terrain 디테일 기능) |
| 에디터 스크립트 + prefab 배치 | 나무, 바위, 소품을 prefab GameObject로 흩뿌리기 (GPU Resident Drawer로 그림), 길, 서식지 위치 표시 |
| 직접 배치 | 서식지 중심 장식처럼 보기 좋음이 중요한 좁은 곳 |
| 위치 표시만 | 거점. 위치 표시 오브젝트만 두고, 건물과 기능 오브젝트는 사용자가 추가한다 |

- 에디터 스크립트는 `map-builder`가 `Assets/Scripts/World/Editor/` 아래에 작성하고, 실행과 스크린샷 확인은 메인 Claude가 Unity MCP로 한다.
- 직접 배치는 오브젝트와 스크린샷마다 토큰이 많이 들므로 위 표의 좁은 곳에만 쓴다.
- 모든 맵 작업은 `## 성능 기준`을 지키며 만들고, 작업이 끝날 때마다 측정한다.
- 자연스러움, 분위기 같은 최종 다듬기는 사용자가 유니티 에디터에서 한다.

## 좌표 규칙

- 맵은 3 × 3 격자. 열 A~C는 서쪽에서 동쪽, 행 1~3은 북쪽에서 남쪽 방향이다.
- 칸 크기는 균일하지 않다 (임시값). 가운데 열 B와 가운데 행 2는 500m, 바깥 열 A, C와 바깥 행 1, 3은 1000m. 전체 2.5km × 2.5km.

| 열 / 행 | 월드 범위 |
| --- | --- |
| A (서) | x -1250 ~ -250 |
| B (가운데) | x -250 ~ 250 |
| C (동) | x 250 ~ 1250 |
| 1 (북) | z 250 ~ 1250 |
| 2 (가운데) | z -250 ~ 250 |
| 3 (남) | z -1250 ~ -250 |

- 위쪽(+Z)이 북쪽이다. 의뢰서의 서식 방향 (예: 거점 기준 북동)은 이 기준으로 계산한다.
- 거점은 맵 정중앙 (중앙 칸 B2의 중심) = 월드 원점 (0, 0)에 있다.
- 방향은 거점 중심에서 서식지 중심을 향한 8방위 (북, 북동, 동, 남동, 남, 남서, 서, 북서)로 나타낸다.

## 거점

- 위치 : 월드 원점. 위치 표시 오브젝트만 둔다.
- 건물, 총기 상점, 의뢰 게시판, 회복 지점은 사용자가 직접 추가한다.
- 크기 : 미정 (사용자가 건물을 놓은 뒤 정한다. 거점 주변을 평평하게 다듬을 범위가 이 값을 따른다)

## 구역

> 결정 : 2026-11-09. 중앙을 둘러싼 8방향에 구역을 하나씩 둔다. (2026-11-10 3 × 3 격자로 변경, 한 칸 = 한 구역)

```
      A (1000m)   B (500m)   C (1000m)
1 |    북서    |    북    |    북동    |   (1000m)
2 |    서      |   중앙   |    동      |   (500m)
3 |    남서    |    남    |    남동    |   (1000m)
```

| 구역 | Hierarchy 부모 | 칸 | 크기 (동서 × 남북) | 테마 |
| --- | --- | --- | --- | --- |
| 중앙 | `Center` | B2 | 500 × 500m | 거점과 들판 (숲, 드문드문, 개활지) |
| 북 | `North` | B1 | 500 × 1000m | 높은 산지와 호수 (데모 지형). 호수에서 시작한 강이 남쪽으로 흐름 (이슈 #5) |
| 북동 | `NorthEast` | C1 | 1000 × 1000m | 북쪽 산지가 이어짐 (이슈 #5). 나머지 테마 미정 |
| 동 | `East` | C2 | 1000 × 500m | 미정 |
| 남동 | `SouthEast` | C3 | 1000 × 1000m | 미정 |
| 남 | `South` | B3 | 500 × 1000m | 강변 유적 도시 (이슈 #11). 강이 가운데를 지나감 |
| 남서 | `SouthWest` | A3 | 1000 × 1000m | 초원 (이슈 #9) |
| 서 | `West` | A2 | 1000 × 500m | 침엽수림 (이슈 #7) |
| 북서 | `NorthWest` | A1 | 1000 × 1000m | 북쪽 산지가 이어짐, 맵 최고점 (이슈 #5). 나머지 테마 미정 |

- 테마는 자연 지형 (예: 침엽수림, 바위 산악, 초원, 유적, 호숫가) 중에서 구역 작업 때 사용자가 정한다.
- 구역 경계에서 지형을 끊지 않는다 (결정 : 2026-11-10). 산맥처럼 이어지는 지형은 옆 구역으로 자연스럽게 이어 만들고, 옆 구역의 나머지는 그 구역 작업 때 맞춘다. 예 : 북쪽 산맥은 북서, 북동 구역으로 이어진다.
- 구역마다 다른 몬스터가 나온다 (`GameDesign.md`). 구역별 몬스터는 미정.
- 룬 돌 (`StandingStones/Prefab_RockFormation_*`)은 랜드마크로 쓴다 (결정 : 2026-11-10). 위치는 구역 작업 때 Claude가 판단해 넣는다 (예: 호숫가, 정상부, 서식지 근처).
- 구역의 배치물은 그 구역의 Hierarchy 부모 아래에 둔다. 나무는 `<구역>/Trees`, 바위·소품은 `<구역>/Rocks`.

## 중앙 지역 (이슈 #3)

> 2026-11-11 : 500 × 500m, 바탕 높이 30m로 다시 만든 값이다 (이슈 #5).

| 항목 | 값 (임시값) |
| --- | --- |
| 언덕 | 기준 30m, 진폭 ±25m (실제 21.3 ~ 35.1m, 강이 깎은 곳 포함). 거점 반경 30m 평지, 30 ~ 180m에서 이어짐. 경계 안쪽 100m에서 30m로 줄어듦 |
| 분포 | 빽빽한 숲 / 드문드문 / 개활지 = 20 / 45 / 35% |
| 나무 밀도 (1ha당) | 숲 100 ~ 150, 드문드문 5 ~ 15, 개활지 0. 고사목 약 5%, 거대목 약 1% (숲만) |
| 바위·소품 밀도 (1ha당) | 숲 안 10 ~ 20, 밖 1 ~ 3 |
| 거점 비움 반경 | 40m (나무, 바위, 식생 없음) |
| 바닥 식생 | Dreamscape Terrain용 풀, 고사리, 낙엽, 꽃 |

- 에디터 스크립트 : `Assets/Scripts/World/Editor/`의 `Tools/Map/` 메뉴 1 ~ 4를 순서대로 실행한다. 언덕(2)을 다시 실행하면 3, 4도 다시 실행한다. 강과 등산로가 생긴 뒤로는 북쪽 줄과 함께 다시 만들 때는 `## 북쪽 줄 (이슈 #5)`의 실행 순서를 따른다.

## 북쪽 줄 (이슈 #5)

> 결정 : 2026-11-10. 처음 만든 북쪽 산 (메뉴 5, 정상 290m)이 인공적으로 보여, 북쪽 줄 (A1 ~ C1)은 Dreamscape 데모 지형 (`DemoTerrain_V2.0.asset`)을 최대한 그대로 따라 만든다. 데모 에셋은 읽기만 하고, 우리 에디터 스크립트로 옮겨 만든다.

- 이식 창 : 데모 지형의 1500 × 1000m를 크기 그대로 (1:1), 위에서 볼 때 180도 돌려 x -750 ~ 750, z 250 ~ 1250에 놓는다. 데모의 낮은 호수 쪽이 중앙과 맞닿고, 높은 봉우리가 맵 북쪽 끝으로 간다.
- 창 밖 (A1, C1의 |x| > 750) : 데모 지형을 거울처럼 접어 이어 가며 낮은 언덕으로 낮춘다. 지면 칠, 바닥 식생, 나무, 바위는 규칙으로 채운다.
- 남쪽 경계 (z = 250)는 중앙의 바탕 높이와 정확히 같게 이어 붙인다.

| 항목 | 값 (임시값) |
| --- | --- |
| Terrain 높이 한계 | 400m (데모 높이 41.5 ~ 397.9m를 담기 위해 300m에서 올림) |
| 최고점 | 370.5m, A1 (-592, 1199) |
| 호수 수면 | 38m (강이 호수 → 중앙 → 남쪽으로 내리막으로 흐르는 최저값) |
| 창 밖 나무·바위 밀도 (1ha당) | 높이대별. 기슭 (~160m) 나무 30 ~ 50, 바위 1 ~ 3 / 중턱 나무 5 ~ 15, 바위 5 ~ 10 / 정상 부근 (310m ~) 나무 0, 바위 10 ~ 20. 높이대 경계는 ±15m 흔듦 |
| 빈 풀밭 채우기 (메뉴 9-3) | 풀 레이어 비중 0.5 초과, 반경 10m 안에 바닥 식생이 하나도 없는 칸만 채운다 (경사 35° 미만, 물가와 등산로 밖). 정상 부근도 채운다 |
| 룬 돌 | 등산로 경유점 네 곳 (호수 서쪽·동쪽 물가, 서쪽·동쪽 봉우리) 옆, 길 가장자리에서 3 ~ 10m |

- 데모 식생 가장자리와 메뉴 9-3이 채운 풀밭 사이의 폭 5 ~ 8m 틈은 의도적으로 남겨 둔다 (결정 : 2026-11-11). 자연스러운 빈터로 보고 고치지 않는다.
- 데모 절벽 벽 (예: 호수 서쪽 (-40, 890)의 높이 약 40m 벽)과 구역 경계 (x = ±250) 위의 가파른 비탈은 지형의 일부다. 끊긴 자국이 아니다 (2026-11-11 높이 단면으로 확인).
- 에디터 스크립트 실행 순서 (처음부터 다시 만들 때)

```
1 → 1-1 → 2 → 5-1 → 6 → 7 → 7-1 → 3 → 8-1 → 9-1 → 4 → 9-2 → 9-3 → 11 → 12 → 13 → 14 → 15 → 16 → 17 → 18 → 19 → 10
```

| 메뉴 | 하는 일 |
| --- | --- |
| 5-1. 북쪽 지형 (데모 이식) | 데모 높이맵을 북쪽 줄에 옮긴다. 메뉴 5를 대신한다 |
| 6. 호수 만들기 | 데모 호수 자리에 호수 수면 (`Lake.prefab`)을 놓는다 |
| 7. 강 만들기 | 호수에서 남쪽 맵 끝까지 강바닥을 깎고 수면 (`RiverNorth`, `RiverCenter`, `RiverSouth`)을 놓는다 |
| 7-1. 등산로 만들기 | 거점에서 북쪽 봉우리까지 두 갈래 길을 만들고 경로를 `Assets/Settings/World/TrailPaths.json`에 저장한다 |
| 8-1. 북쪽 데모 오브젝트·나무 이식 | 데모 씬의 절벽, 바위, 유적, 나무를 옮기고 창 밖과 룬 돌을 채운다. 메뉴 8을 대신한다 |
| 9-1. 지면과 바닥 식생 전체 초기화 | 맵 전체 지면을 풀로, 바닥 식생을 비운다 |
| 9-2. 북쪽 데모 지면 이식 | 데모 지면 칠과 바닥 식생을 옮기고 물가, 등산로를 덧칠한다. 메뉴 9를 대신한다 (메뉴 9는 비활성) |
| 9-3. 북쪽 빈 풀밭 채우기 | 9-2 뒤에 남은 빈 풀밭에 바닥 식생을 채운다. 9-2를 다시 실행하면 9-3도 다시 실행한다 |
| 10. 조명·안개·하늘 (데모 설정) | 후처리, 안개, 하늘, 환경광, 해를 데모 씬 설정으로 맞춘다 |

- 중앙 나무·바위 (메뉴 3)는 강과 등산로를 피하므로 7-1 다음에 실행한다.
- 지형을 다시 만드는 메뉴 (5-1, 6, 7, 7-1)는 앞 메뉴의 결과를 읽으므로, 하나를 다시 실행하면 그 뒤 메뉴도 순서대로 다시 실행한다. 자세한 조건은 각 스크립트 머리말 주석에 있다.

## 서쪽 침엽수림 (이슈 #7)

> 결정 : 2026-11-11. 서쪽 구역 (A2)은 침엽수림. 지형과 나무는 규칙으로 채우고, 눈에 띄는 랜드마크만 prefab으로 직접 구성한다. 길은 두지 않는다.

| 항목 | 값 (임시값) |
| --- | --- |
| 언덕 | 바탕 30m 위로만 솟음 (바탕 + 0 ~ 25m), 경계 안쪽 100m에서 30m로 줄어듦. 실제 30.0 ~ 46.9m. 네 경계 줄은 30m 그대로라 A1, B2, A3 높이를 바꾸지 않는다 |
| 분포 | 숲 / 드문드문 / 빈터 = 60 / 25 / 15% (구분 노이즈는 중앙과 같은 무늬) |
| 나무·바위 밀도 | `## 중앙 지역` 표와 같은 값 |
| 서식지 위치 표시 | `West/Habitat` (-750, 0), 거점 기준 방위 270° (서), 반경 80m. 반경 안은 빈터 (나무, 바위, 랜드마크 없음) |

- 랜드마크 4곳 (`West/Landmarks`) : Dreamscape prefab으로 직접 조립한다 (배치도는 `MapWestScatter.cs`의 상수). 데모 씬 묶음은 옮기지 않는다 (북쪽과 같은 배치 반복 방지).

| 랜드마크 | 구성 | 바닥 반지름 |
| --- | --- | --- |
| 무너진 신전 터 | 계단, 기둥 6, 부서진 아치, 벽 조각, 바닥 벽돌 (19조각). 숲 구분 | 15m |
| 큰 바위 무리 | 큰 바위 8 (1.5 ~ 3배), 절벽 조각 1, 작은 돌 4 (13조각) | 21m |
| 선돌 원 | 선돌 9개를 반지름 10m 원으로 + 가운데 1 (10조각) | 13m |
| 버려진 사냥꾼 야영지 | 40 × 40m에 60조각 (밀도 약 0.037개/m²). 큰 불 자리와 앉는 통나무, 작은 불 자리, 벌목터 (그루터기 6, 도끼 2), 장작 무더기 4, 수레 2와 바퀴 2, 해골 3. 드문드문 또는 빈터 구분 | 26m |

## 남서쪽 초원 (이슈 #9)

### 나무, 바위, 소품 배치 방식 (결정 : 2026-11-09)

- 많이 놓는 나무, 바위, 소품은 **prefab GameObject로 배치하고 URP GPU Resident Drawer로 묶어 그린다.** Terrain 나무 기능은 쓰지 않는다.
    - 이유 : 중앙 지역 측정에서 Terrain 나무 (LOD prefab은 한 그루씩 따로 그림) 대비 Batches가 약 5,500 → 1,400으로 줄고 FPS는 같거나 높았다. prefab의 Collider가 그대로 동작한다.
    - 필요한 설정 (켜져 있어야 함) : URP 에셋 `PC_RPAsset`의 GPU Resident Drawer = Instanced Drawing, Renderer의 Rendering Path = Forward+, SRP Batcher 켬, `Project Settings > Graphics`의 BatchRendererGroup Variants = Keep All.
- 배치 규칙
    - LOD가 있고 셰이더가 DOTS 인스턴싱을 지원하는 prefab만 쓴다. 아니면 쓰기 전에 보고한다.
    - 원본 prefab을 고치지 않고 `PrefabUtility.InstantiatePrefab`으로 배치한다. Static 플래그는 켜지 않는다 (Static Batching과 섞지 않기 위해).
    - prefab에 Collider가 없는 종류는 배치할 때 씬 인스턴스에 충돌체를 붙인다 (나무는 CapsuleCollider, 바위·통나무는 convex MeshCollider).
    - 에디터 스크립트를 다시 실행하면 그 구역의 `Trees`, `Rocks` 아래를 지우고 같은 seed로 다시 만든다.
- 되돌리는 조건 : 구역을 추가할 때마다 측정해서, 아래 중 하나에 해당하면 Terrain 나무 기능이나 밀도 조정으로 되돌리는 안을 사용자에게 제안한다.
    - 60FPS 아래로 떨어짐
    - 씬 저장, 열기, Play 진입이 눈에 띄게 느려짐 (걸린 시간을 보고에 적는다)

### 공통

- 먼 곳은 안개로 가린다. 그리는 거리 바깥이 갑자기 끊겨 보이지 않게 한다.
- 그리는 거리, 밀도를 늘려 보기 좋음을 얻으려면 먼저 측정 결과와 함께 사용자에게 제안한다.
- 측정과 보고
    - 작업이 끝날 때마다 **Play 모드**에서 같은 위치 (거점, 가장 빽빽한 곳, 가장 높은 곳, 개활지 가장자리)의 FPS, Batches, Tris를 측정한다. 눈높이 1.7m.
    - Play 모드 밖에서 카메라를 직접 렌더해 잰 시간은 에디터 고정 지연이 섞여 쓰지 않는다.
    - Unity 창이 포커스를 잃으면 Play 모드 프레임이 멈추므로, 측정하는 동안만 `Application.runInBackground = true`로 둔다 (저장되지 않는 실행 중 값).
    - 첫 측정값은 준비 시간이 섞일 수 있으니, 같은 위치를 두 번 재서 안정된 값을 쓴다.
    - 측정값과 맵 전체 배치 GameObject 수를 검수 요청의 "확인 결과"에 적는다. 에디터 수치는 "에디터 측정"이라고 표시한다.
    - 60FPS 아래로 떨어지면 다음 작업으로 넘어가지 않고, 밀도나 거리를 줄이는 안을 사용자에게 제안한다.

## 임시값

> 모든 값은 임시값이다. 배치 후 사용자가 유니티 에디터에서 보기 좋음, 저격 시야, 성능을 확인하며 조정한다.
> 밀도는 1ha (100m × 100m)당 개수다. 중앙 칸 (500m × 500m) = 25ha, 바깥 모서리 칸 (1000m × 1000m) = 100ha.

| 항목 | 값 (임시값) |
| --- | --- |
| 길 폭 | 4m |
| 숲, 들판의 나무 밀도 | 중앙은 `## 중앙 지역` 표, 북쪽 줄은 데모 배치 그대로 (창 밖은 `## 북쪽 줄 (이슈 #5)` 표). 다른 구역은 구역 작업 때 `## 성능 기준`의 측정 결과를 보고 결정 |
| 서식지 반경 | 미정 |
| 높은 지형 높이 (주변 지면 기준) | 미정 |

## 배치할 때 확인할 것

- 에셋 구성 확인 : 구역 작업 전에 Dreamscape의 나무, 바위, 식생 prefab에 LOD와 Collider가 있는지, URP에서 머티리얼이 깨지지 않는지 확인한다.
    - 확인 결과 (2026-11-09) : `Prefab_Mushroom_*`는 렌더러 없음 → 쓰지 않는다. `Conifer_03`, `Conifer_06`, `SmallRock_01·02`, `HollowTrunk`는 Collider 없음 → 배치할 때 붙인다.
    - 확인 결과 (2026-11-10) : `Prefab_Cliff_*`는 셰이더 (CliffAuto)가 DOTS 인스턴싱을 지원하지 않아 GPU Resident Drawer가 몸체를 그리지 못하고 그림자만 남는다 → 씬 인스턴스에 `DisallowGPUDrivenRendering` 컴포넌트를 붙여 쓴다 (원본 prefab은 고치지 않는다). 하나씩 따로 그려지므로 포인트에만 둔다. 물 셰이더도 DOTS 인스턴싱을 지원하지 않으므로 같은 처리를 한다.
    - 확인 결과 (2026-11-10) : `Prefab_WaterLakeMountains`는 패키지에 없는 메시와 머티리얼을 가리켜 비어 있다 → 쓰지 않고, `SM_WaterPlane.fbx` + `MI_Water_MountainsLake.mat`로 만든 prefab을 쓴다.
    - 확인 결과 (2026-11-11) : `Prefab_WallRuin`은 루트 LODGroup의 렌더러 18개가 자식 LODGroup 10개에도 모두 등록되어 있어, 씬을 불러올 때마다 "Renderer is registered with more than one LODGroup" 경고를 낸다 → 쓰지 않는다. 메뉴 8-1이 옮겨 놓는 북쪽, 북동쪽 유적 2개는 맨 위 LODGroup만 지워 경고를 없앤다 (자식 LODGroup이 LOD를 맡는다. 원본 prefab은 고치지 않는다).
    - 확인 결과 (2026-11-11) : 일부 prefab (예: `Prefab_Cart`)은 메시 범위 (bounds)가 실제 모양보다 아래로 0.75m 크게 잡혀 있어, 범위로 높이를 맞추면 뜬다 → 랜드마크 조각의 높이와 뜸·묻힘 검사는 메시 정점 기준으로 한다.
- 데모 씬 : Dreamscape 데모 씬 중 이 팩에 없는 prefab을 참조하는 씬은 에셋을 다시 읽을 때마다 Console 오류를 만든다. 오류를 만드는 데모 씬은 사용자 승인 후 삭제한다.
- 배치 결과의 보기 좋음과 플레이 감각은 사용자가 유니티 에디터에서 직접 확인한다.

## 미정

- 구역별 테마, 서식지, 길, 높은 지형
- 구역별 몬스터
- 거점 크기
- 거점과의 거리에 따른 몬스터 난이도 차이를 둘지 여부
- 칸 크기 (중앙 500m, 바깥 1000m) 확정 여부
- 강 폭, 거점 근처를 지나는 위치, 건너는 곳
