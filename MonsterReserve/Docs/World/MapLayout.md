# 맵 배치 (Map Layout)

> 온디맨드 문서. 맵 구조물 배치 작업 시 `map-builder`가 읽는다.
> 2026-11-09 맵 방향 변경 : 에셋은 Dreamscape Nature Mountains 하나, 맵은 2km × 2km. 결정 이유는 `Docs/Design/GameDesign.md` 결정 기록에 있다.
> 배치도 이미지 `Docs/World/map-diagram.png`는 이전 5km 맵 기준이라 지금은 맞지 않는다. 구역이 정해지면 새로 그린다.

---

## 작업 방식

> 결정 : 2026-11-09. 넓은 면적은 규칙 기반으로 채워 토큰과 성능을 아끼고, 눈에 띄는 좁은 곳만 직접 다듬는다.

| 방식 | 쓰는 곳 |
| --- | --- |
| Unity Terrain | 바탕 지면, 높은 지형, 바닥 식생 (Terrain 디테일 기능) |
| 에디터 스크립트 + prefab 배치 | 나무, 바위, 소품을 prefab GameObject로 흩뿌리기 (GPU Resident Drawer로 그림), 길, 서식지 위치 표시 |
| 직접 배치 | 서식지 중심 장식처럼 보기 좋음이 중요한 좁은 곳 |
| 위치 표시만 | 거점. 위치 표시 오브젝트만 두고, 건물과 기능 오브젝트는 사용자가 추가한다 |

- 에디터 스크립트는 `map-builder`가 `Assets/Scripts/World/Editor/` 아래에 작성하고, 실행과 스크린샷 확인은 메인 Claude가 Unity MCP로 한다.
- 직접 배치는 오브젝트와 스크린샷마다 토큰이 많이 들므로 위 표의 좁은 곳에만 쓴다.
- 모든 맵 작업은 `## 성능 기준`을 지키며 만들고, 작업이 끝날 때마다 측정한다.
- 자연스러움, 분위기 같은 최종 다듬기는 사용자가 유니티 에디터에서 한다.

## 좌표 규칙

- 맵은 4 × 4 격자. 열 A~D는 서쪽에서 동쪽, 행 1~4는 북쪽에서 남쪽 방향이다.
- 한 칸 = 500m (임시값). 전체 2km × 2km.
- 위쪽(+Z)이 북쪽이다. 의뢰서의 서식 방향 (예: 거점 기준 북동)은 이 기준으로 계산한다.
- 거점은 맵 정중앙 (B2, C2, B3, C3 네 칸이 만나는 점) = 월드 원점 (0, 0)에 있다.
- 방향은 거점 중심에서 서식지 중심을 향한 8방위 (북, 북동, 동, 남동, 남, 남서, 서, 북서)로 나타낸다.

## 거점

- 위치 : 월드 원점. 위치 표시 오브젝트만 둔다.
- 건물, 총기 상점, 의뢰 게시판, 회복 지점은 사용자가 직접 추가한다.
- 크기 : 미정 (사용자가 건물을 놓은 뒤 정한다. 거점 주변을 평평하게 다듬을 범위가 이 값을 따른다)

## 구역

> 결정 : 2026-11-09. 중앙을 둘러싼 8방향에 구역을 하나씩 둔다.

```
      A      B      C      D
1 |  북서 |  북   |  북   |  북동 |
2 |  서   |  중앙 |  중앙 |  동   |
3 |  서   |  중앙 |  중앙 |  동   |
4 |  남서 |  남   |  남   |  남동 |
```

| 구역 | Hierarchy 부모 | 범위 (칸) | 테마 |
| --- | --- | --- | --- |
| 중앙 | `Center` | B2 ~ C3 | 거점과 들판 (숲, 드문드문, 개활지) |
| 북 | `North` | B1 ~ C1 | 미정 |
| 북동 | `NorthEast` | D1 | 미정 |
| 동 | `East` | D2 ~ D3 | 미정 |
| 남동 | `SouthEast` | D4 | 미정 |
| 남 | `South` | B4 ~ C4 | 미정 |
| 남서 | `SouthWest` | A4 | 미정 |
| 서 | `West` | A2 ~ A3 | 미정 |
| 북서 | `NorthWest` | A1 | 미정 |

- 테마는 자연 지형 (예: 침엽수림, 바위 산악, 초원, 유적, 호숫가) 중에서 구역 작업 때 사용자가 정한다.
- 구역마다 다른 몬스터가 나온다 (`GameDesign.md`). 구역별 몬스터는 미정.
- 구역의 배치물은 그 구역의 Hierarchy 부모 아래에 둔다. 나무는 `<구역>/Trees`, 바위·소품은 `<구역>/Rocks`.

## 중앙 지역 (이슈 #3)

| 항목 | 값 (임시값) |
| --- | --- |
| 언덕 | 기준 50m, 진폭 ±25m (실제 26.5 ~ 58.9m). 거점 반경 30m 평지, 30 ~ 180m에서 이어짐. 경계 안쪽 100m에서 50m로 줄어듦 |
| 분포 | 빽빽한 숲 / 드문드문 / 개활지 = 20 / 45 / 35% |
| 나무 밀도 (1ha당) | 숲 100 ~ 150, 드문드문 5 ~ 15, 개활지 0. 고사목 약 5%, 거대목 약 1% (숲만) |
| 바위·소품 밀도 (1ha당) | 숲 안 10 ~ 20, 밖 1 ~ 3 |
| 거점 비움 반경 | 40m (나무, 바위, 식생 없음) |
| 바닥 식생 | Dreamscape Terrain용 풀, 고사리, 낙엽, 꽃 |

- 에디터 스크립트 : `Assets/Scripts/World/Editor/`의 `Tools/Map/` 메뉴 1 ~ 4를 순서대로 실행한다. 언덕(2)을 다시 실행하면 3, 4도 다시 실행한다.

## 서식지, 길

- 미정. 구역 테마가 정해진 뒤 함께 정한다.
- 서식지는 거점 기준 방향이 서로 다르게 나오도록 8방향 구역에 하나씩 둔다 (의뢰서의 방향 안내가 서식지마다 다르게 나오도록).

## 높은 지형 (저격하기 좋은 곳)

- 정해진 저격 지점은 없지만, 구역마다 멀리 내려다볼 수 있는 높은 지형을 하나 이상 둔다.
- 위치와 높이 : 미정 (구역이 정해진 뒤 결정)

## 성능 기준 (맵 작업 필수)

> 목표는 `Docs/TechSpec.md`의 "성능" (빌드 기준 60FPS)이다. 아래 값은 모두 임시 시작값이며, 측정 결과를 보고 사용자와 조정한다.

| 항목 | 값 (임시값) |
| --- | --- |
| 바닥 식생을 그리는 거리 (Terrain Detail Distance) | 80m |
| 그림자 거리 (URP Shadow Distance) | 150m |
| 안개 | Linear, 300 ~ 1000m |
| 카메라 Far Clip | 1200m |

### 나무, 바위, 소품 배치 방식 (결정 : 2026-11-09)

- 많이 놓는 나무, 바위, 소품은 **prefab GameObject로 배치하고 URP GPU Resident Drawer로 묶어 그린다.** Terrain 나무 기능은 쓰지 않는다.
    - 이유 : 중앙 지역 측정에서 Terrain 나무 (LOD prefab은 한 그루씩 따로 그림) 대비 Batches가 약 5,500 → 1,400으로 줄고 FPS는 같거나 높았다. prefab의 Collider가 그대로 동작한다.
    - 필요한 설정 (켜져 있어야 함) : URP 에셋 `PC_RPAsset`의 GPU Resident Drawer = Instanced Drawing, Renderer의 Rendering Path = Forward+, SRP Batcher 켬, `Project Settings > Graphics`의 BatchRendererGroup Variants = Keep All.
- 배치 규칙
    - LOD가 있고 셰이더가 DOTS 인스턴싱을 지원하는 prefab만 쓴다. 아니면 쓰기 전에 보고한다.
    - 원본 prefab을 고치지 않고 `PrefabUtility.InstantiatePrefab`으로 배치한다. Static 플래그는 켜지 않는다 (Static Batching과 섞지 않기 위해).
    - prefab에 Collider가 없는 종류는 배치할 때 씬 인스턴스에 충돌체를 붙인다 (나무는 CapsuleCollider, 바위·통나무는 convex MeshCollider).
    - 에디터 스크립트를 다시 실행하면 그 구역의 `Trees`, `Rocks` 아래를 지우고 같은 seed로 다시 만든다.
- 되돌리는 조건 : 구역을 추가할 때마다 측정해서, 아래 중 하나에 해당하면 Terrain 나무 기능이나 밀도 조정으로 되돌리는 안을 사용자에게 제안한다.
    - 60FPS 아래로 떨어짐
    - 씬 저장, 열기, Play 진입이 눈에 띄게 느려짐 (걸린 시간을 보고에 적는다)

### 공통

- 먼 곳은 안개로 가린다. 그리는 거리 바깥이 갑자기 끊겨 보이지 않게 한다.
- 그리는 거리, 밀도를 늘려 보기 좋음을 얻으려면 먼저 측정 결과와 함께 사용자에게 제안한다.
- 측정과 보고
    - 작업이 끝날 때마다 **Play 모드**에서 같은 위치 (거점, 가장 빽빽한 곳, 가장 높은 곳, 개활지 가장자리)의 FPS, Batches, Tris를 측정한다. 눈높이 1.7m.
    - Play 모드 밖에서 카메라를 직접 렌더해 잰 시간은 에디터 고정 지연이 섞여 쓰지 않는다.
    - Unity 창이 포커스를 잃으면 Play 모드 프레임이 멈추므로, 측정하는 동안만 `Application.runInBackground = true`로 둔다 (저장되지 않는 실행 중 값).
    - 첫 측정값은 준비 시간이 섞일 수 있으니, 같은 위치를 두 번 재서 안정된 값을 쓴다.
    - 측정값과 맵 전체 배치 GameObject 수를 검수 요청의 "확인 결과"에 적는다. 에디터 수치는 "에디터 측정"이라고 표시한다.
    - 60FPS 아래로 떨어지면 다음 작업으로 넘어가지 않고, 밀도나 거리를 줄이는 안을 사용자에게 제안한다.

## 임시값

> 모든 값은 임시값이다. 배치 후 사용자가 유니티 에디터에서 보기 좋음, 저격 시야, 성능을 확인하며 조정한다.
> 밀도는 1ha (100m × 100m)당 개수다. 한 칸 (500m × 500m) = 25ha.

| 항목 | 값 (임시값) |
| --- | --- |
| 길 폭 | 4m |
| 숲, 들판의 나무 밀도 | 중앙은 `## 중앙 지역` 표. 다른 구역은 구역 작업 때 `## 성능 기준`의 측정 결과를 보고 결정 |
| 서식지 반경 | 미정 |
| 높은 지형 높이 (주변 지면 기준) | 미정 |

## 배치할 때 확인할 것

- 에셋 구성 확인 : 구역 작업 전에 Dreamscape의 나무, 바위, 식생 prefab에 LOD와 Collider가 있는지, URP에서 머티리얼이 깨지지 않는지 확인한다.
    - 확인 결과 (2026-11-09) : `Prefab_Cliff_*`는 깨진 셰이더 (CliffAuto), `Prefab_Mushroom_*`는 렌더러 없음, `Prefab_WaterLakeMountains`는 메시와 머티리얼 없음 → 쓰지 않는다. `Conifer_03`, `Conifer_06`, `SmallRock_01·02`, `HollowTrunk`는 Collider 없음 → 배치할 때 붙인다.
- 데모 씬 : Dreamscape 데모 씬 중 이 팩에 없는 prefab을 참조하는 씬은 에셋을 다시 읽을 때마다 Console 오류를 만든다. 오류를 만드는 데모 씬은 사용자 승인 후 삭제한다.
- 배치 결과의 보기 좋음과 플레이 감각은 사용자가 유니티 에디터에서 직접 확인한다.

## 미정

- 구역별 테마, 서식지, 길, 높은 지형
- 구역별 몬스터
- 거점 크기
- 거점과의 거리에 따른 몬스터 난이도 차이를 둘지 여부
- 한 칸 크기 (500m) 확정 여부
